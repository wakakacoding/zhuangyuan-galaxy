# B6 前置预研 · 字体阻塞 CSS 治理方案（2026-10-25）

> 结论先行：**M6 验收线（阻塞 CSS ≤30KB gzip）已在 10-24 的字体拆分批达成，无需再动手**。本文档记录现状实测、已落地机制、以及若要进一步压到 ~10KB 的后续可选路线（不在 M6 强制范围）。

## 一、现状实测（main@9237e0d，dist 实测）

| 项 | 数值 | 说明 |
|---|---|---|
| 全站阻塞 CSS | **1 个文件** `about.D8HQGoc1.css` | 43,214 B raw / **8,823 B gzip** |
| 其中 @font-face | 32 条（latin-400 16 + latin-700 16） | 占阻塞 CSS 原始体积约 20KB raw |
| CJK 声明 | 85×2=170 条，**已移出阻塞路径** | `fonts/cjk-400.css` + `cjk-700.css` 异步注入（BaseLayout 末尾 script），各 28KB gzip |
| 字体文件 | 204 个 woff2 于 `dist/fonts/files/` | 共 9.4MB，按 unicode-range 分片按需下载 |
| 页面加载的 CSS 总量 | 阻塞 8.8KB gz + 异步 56KB gz | CJK CSS 非阻塞（页面加载后 link 注入） |

对照 M5-d T7a 基线（202 条 @font-face 全在阻塞 CSS、109KB gzip），**10-24 批已消除主要债务**：阻塞 CSS 从 ~109KB gz 降到 **8.8KB gz**，为原基线 8%。

## 二、已落地机制（不需要重做）

1. `scripts/split-cjk-font.mjs`：把 @fontsource/noto-serif-sc 的声明按 unicode-range 是否含 U+4E00–9FFF 拆为 latin / cjk 两份，产物进 `src/styles/fonts/`。
2. `BaseLayout.astro`：只 `import` latin-400/700（进 Astro 打包的阻塞 CSS）；CJK 两份在 body 末尾 script 动态 `appendChild(link)` 异步注入，`font-display: swap` 保证下载完成前用系统衬线、无不可见文字。
3. latin 分片的 woff2 由 Astro 从 `@fontsource` 打包进 `dist/fonts/files/`（构建产物验证 200 可达）。

## 三、遗留问题（低优先级，记录在案）

### 3.1 阻塞 CSS 内 32 条 latin 声明可再精简

- 现存 12 个 latin 分片（sc-4/5/6/86–91/97–99）共约 99KB woff2。其中 sc-5（15KB）与 sc-86（25KB）是大头，多含西里尔/希腊/数学符号等站内罕用字符。
- **可选路线 A（合并裁剪）**：latin 分片不必按 @fontsource 原样保留——把站内实际用到的 latin/标点字符收集成集合，仅保留覆盖它们的 1–2 条声明（自建子集或用 `subset-font` 工具），阻塞 CSS 内 font-face 可从 32 条降到 ≤4 条，阻塞 CSS 降到 ~6KB gz。
- **可选路线 B（内联 critical）**：latin 部分直接内联进 HTML `<style>`，省一次 CSS 请求。收益小（CSS 本来就是同源首块），不推荐先做。
- **收益评估**：阻塞 CSS 已 8.8KB（目标 ≤30KB），进一步压缩对 LCP/TBT 影响在个位数 ms 级。**建议只在触手可及时顺带做路线 A，不单独立项。**

### 3.2 CJK 异步 CSS 仍会触发 ~170 次字体请求（按需）

- unicode-range 分片机制下浏览器只下载页面实际用到字符所在分片，实测典型人物页触发的 woff2 请求 ≈5–15 个。这不是问题，但 9.4MB 字体库全量进 dist 会让部署制品偏大（当前 dist 整体 ~14MB）。若未来想瘦身，可按站内 656 人名 + 正文语料做**用字审计**，把 0 命中的分片从 `@fontsource` 依赖里剔除（需在 B6 实施前做覆盖回归，防止生僻人名缺字——M6 风险表已列）。

## 四、验收口径建议（B6 实施时）

- 阻塞 CSS ≤30KB gzip：**以线上 `/_astro/*.css` 为准**（本地 dist `base='/'`、线上 `base='/zhuangyuan-galaxy'`，hash 不同，终测一律用线上 URL——T7a 口径坑）。
- Lighthouse 首页 ≥90：字体债已清，剩余 TBT 主因是 `client:only` 水合（StarMapGate/GeoMap），属渲染优化范畴，不是 B6 能动的。
- 真机分数回填仍归用户侧（T7a 挂账项）。

## 五、建议

1. **M6 表内 B6 从「实施」降级为「验证 + 收尾」**：验收线已达标，只需 11 月跑一次线上 Lighthouse 回填分数，确认 ≥90 且稳定即可关闭。
2. 路线 A（latin 再精简）挂 M7 储备，不占 M6 工时。
3. `split-cjk-font.mjs` 的产物与脚本已入 CI 链（build 隐含依赖），无需额外守卫；若未来更换字体源，需重跑该脚本并复核 latin/cjk 切分边界。
