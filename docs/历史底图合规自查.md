## 二、自查方法

1. **脚本化几何解析**：遍历八朝切片，统计面数／环数／顶点数／要素类型分布／四至（四极经纬）／包围盒。

### 4.1 历史疆域表达（P0 —— 本次自查新发现，须整改）

**事实**：八朝切片中有 **7 朝混入台湾本岛面**，且都以 `type: 非政区国土` 标注：

| 朝 | 要素名 | type | CHGIS 起止年 | 几何范围 | 质心 |
|---|---|---|---|---|---|
| 唐 | 流求 | 非政区国土 | 589–1127 | 120.06–121.99E, 21.96–25.30N | 121.00, 23.62 |
| 五代 | 流求 | 非政区国土 | 589–1127 | 同上 | 121.00, 23.62 |
| 宋 | 流求 | 非政区国土 | 589–1127 | 同上 | 121.00, 23.62 |
| 辽 | 流求 | 非政区国土 | 589–1127 | 同上 | 121.00, 23.62 |
| 金 | 流求 | 非政区国土 | 1128–1278 | 同上 | 121.04, 23.62 |
| 元 | 琉球 | 非政区国土 | 1324–1368 | 同上 | 121.02, 23.67 |
| 明 | 台湾 | 非政区国土 | 1573–1661 | 同上 | 121.02, 23.67 |
| 清 | （无） | —— | —— | —— | —— |

**问题**：

1. **史实层面**：唐、五代、宋（含辽）、金、元、明均未在台湾设治（元设澎湖巡检司，属泉州路；清康熙二十三年 1684 始设台湾府）。把台湾本岛画入唐／宋／明疆域，与《地图管理条例》第十条(二)「按照实际历史疆界绘制」及《公开地图内容表示规范》第三条相悖，也违反条例第九条「正确反映各要素的地理位置、形态、名称及相互关系」。
2. **渲染层面**：`GeoMap.tsx` 的 `series[0]`（历史政区层）对切片内**全部**面统一使用 `areaColor: dColor + '14'`（朝色淡填）＋ `borderColor: dColor + '59'` 描边，**未按 `type` 区分**；hover tooltip 还会显示「流求」「琉球」「台湾」等名称。视觉上等同于「该岛属该朝疆域」，属"明确归属"表达，与《公开地图内容表示规范》第十一条「归属不明的岛屿……应当作水域设色、留白色或者不予表示」的立法取向相抵触。
3. **来源层面**：CHGIS 用 `非政区国土`（非行政建置）这一类型本身是有意保留的保守标注，但本站切片只保留 `name/type/beg/end` 四字段，前端又未使用 `type`，导致这一保守语义**在传播链路中丢失**。

**整改建议（二选一，推荐 A）**：

- **方案 A（推荐，改动最小）**：在 `scripts/build-geo-maps.ts` 的 mapshaper 管线中增加排除条件，过滤 `TYPE_CH = '非政区国土'`（或至少排除名称属「流求／琉球／台湾／琉球国」者），使七朝切片不含该类面；**清 1820 的「台湾府」（type=府，1684–1875）属正常政区，必须保留**。重跑 `npm run build:maps && npm run build:data`，并在 `data/CHANGELOG.md` 记一行。
- **方案 B（后备）**：保留数据但在前端按 `type` 分流——`非政区国土` 面改为 `areaColor: 'transparent'`＋虚线描边，tooltip 文案改为「非政区（该朝未设治）」，并在图下注入说明。改动面更大，且史学解读成本转移给读者，故列为后备。

> 附：同源问题也影响「辽」朝切片的独立性，见 4.5。

### 4.5 「辽」切片的独立性缺陷（P1，属 4.1 同类）

**事实**：`liao.json` 与 `song.json` **100% 同源**——164 个要素的「名称＋顶点序列」集合完全相同，且 `beg/end` 属性亦逐条相同。

```
song 键数 164 / liao 键数 164
几何+名称完全相同: True
属性不同的条数: 0
仅宋有: [] ；仅辽有: []
```

即：**用户点「辽」看到的是北宋 1111 年政区**，辽的上京道／东京道／中京道等一概未呈现。`dynasties.yaml` 的 `map_note` 已有声明，方向正确（诚实标注优于静默替用），但措辞过时（含已撤除的"现代省界"，见 4.2）。

**建议**：① 保留诚实的 `map_note` 并修正措辞；② 若要真正呈现辽境，需在 CHGIS 之外另找辽代政区数据源（须重新走 SOURCES 登记与合规核对），列入后续里程碑评估，不在 T7c 范围。

### 4.6 主动扩检：审核、资质、精度、地名、敏感内容（P0 决策项 ＋ 多项 ✅）

**① 地图审核（P0 决策项）**——本项指令未列，但属条例核心义务，必须提出：

- 本站面**向公众开放**（GitHub Pages 公网可访问），提供**历史政区地图的编制＋互联网展示**，符合条例第二条适用范围（「向社会公开的地图的编制、审核、出版和互联网地图服务」）。
- 条例第十五条例外仅限「景区图、街区图、地铁线路图等**内容简单**的地图」；《审核规定》第六条三项豁免中，第(三)项明文要求**不涉及……历史疆界**——**本站核心内容恰为历史疆界表达**，故**不落入任何豁免**。
- 条例第十七条(四)／《审核规定》第七条(五)明文将「**历史地图**」划归**自然资源部**审核；第二十条并规定「历史地图没有明确审核依据的，由国务院测绘地理信息行政主管部门商外交部进行审核」。
- 第二十一条要求核发审图号，第二十二条要求「在地图或者附着地图图形的产品的适当位置**显著标注审图号**」。**当前本站无审图号。**
- 第四十九条罚则：应当送审而未送审的，责令改正、警告、没收、可处 10 万元以下罚款。

**客观结论**：**本站地图页处于"未履行地图审核"状态**。这不是技术缺陷，而是制度性合规缺口，须由项目方决策。可选路径（按成本从低到高）：

1. **咨询留痕（最低成本，建议立即执行）**：通过自然资源部门户「服务—网上办事—测绘—地图审核—在线办理」或政务大厅（010-63880129）就"学术性历史政区示意 + 籍贯散点"问询口径，取得书面答复后归档进 `docs/`。M5 规划中「上线前自查」已预留此项位置。
2. **送审**：报自然资源部审核。注意条例第十六条要求送审材料含「地图编制单位的**测绘资质证书**」——个人／开源项目不具资质，需委托有资质单位，成本与周期最高。
3. **降低公开程度或改变表达形态**：例如将来访范围限定为非公开渠道，或改为不呈现地理轮廓的抽象关系图（不构成"地图"），或仅引用**已具审图号的公益性地图**（对应《审核规定》第六条第(一)项豁免）。
4. **维持现状＋书面风险接受**：明确记录"已知悉未送审状态及第四十九条罚则，决定在 X 时点前处理"，避免后续被动。

> 本报告只做条款比对与客观陈述，不构成法律意见；最终定性建议向自然资源主管部门或专业法务确认。

**② 互联网地图服务资质（✅ 不构成）**：本站为**静态历史地图展示**，不提供地理位置定位、地理信息上传标注、地图数据库开发服务，未落入条例第三十三条「互联网地图服务单位」定义，**无需测绘资质证书**，亦不适用第三十四条（服务器境内）、第三十八条（使用经审核批准的地图＋备案）等专章义务。**但**条例第十五条的审核义务与是否构成"互联网地图服务单位"**无关**，仍适用（见 ①）。

**③ 平面精度（✅）**：规范第十九条要求"表现地为我国境内的地图平面精度应当不优于 10 米（不含）"。本站切片输出 `precision=0.01`（≈1.1 km），**远粗于红线**（越粗越安全），无高精度地理信息泄露风险。

**④ 地名表示（✅）**：GeoMap 默认 `label.show = false`，图上不注任何地名；tooltip 呈现的是唐／宋／明等**历史政区名**（如"泽州""黄州路"），不涉及规范第十三条（地名管理）与第十四条（须括注"海参崴／双城子／伯力／海兰泡／库页岛／尼尔琴斯克／庙街／外兴安岭"八处）的现代地名规范化问题。`data/geo/placenames.csv` 的现代地名仅用于**坐标定位**，不上图。

**⑤ 不得表示内容（✅）**：八朝切片共 1,538 个面全部为历史行政区划／非政区国土，`properties` 仅含 `name/type/beg/end` 四字段，不含规范第二十条（军事设施、核设施、重要管线、卫星导航基准站等）与第二十一条（军事禁区属性、桥梁限值、库容坝高等）任何要素。

**⑥ UGC 上传标注（✅）**：站内无地图上传／标注功能，勘误通道为 GitHub Issue 结构化表单（文字），不构成条例第三十七条「通过互联网上传标注」情形。

### 4.7 数据许可（CHGIS EULA）冲突（P0 —— 本次自查新发现）

**原文**（`data/geo/chgis/raw/v6_time_pref_pgn_utf_wgs84/CHGIS_V6_README.txt`）：

> License: free for academic research, **no commercial use, resale, or redistribution permitted**.

**本站现状**：

- `public/data/maps/*.json`（八朝切片，约 2.0 MB）**已入公开 Git 仓库**；`.gitignore` 注释明文写着「CHGIS 原始 shp（109MB…）产物已入 `public/data/maps/`」；
- 站点部署于 GitHub Pages，切片 JSON 可被任意访客直接下载；
- `data/geo/SOURCES.md` §4「仓库管理约定」把"入 Git"写成了**既定设计**（理由：使无 CHGIS 原始数据时亦可构建网站）。

**判定**：将 CHGIS 衍生数据（切片）公开分发，落在 EULA 明确禁止的 `redistribution` 语义内；公开仓库＋公网分发进一步使其难以被认定为"仅限学术研究使用"。**这是当前最容易被外部（含数据提供方）指出的合规硬伤，优先级不低于地图审核问题。**

**可选路径**：

1. **不再分发衍生数据（推荐）**：将 `public/data/maps/*.json` 移出版本控制（加入 `.gitignore`），改为**构建期生成**；CI 构建需先按 `SOURCES.md` 从 Harvard Dataverse 获取原始数据（下载页面的 EULA 接受动作由部署者完成）。代价：GitHub Actions 需新增下载步骤（约 31 MB，含解压），构建时间与网络依赖上升；`build-geo-maps.ts` 现有的"无原始数据时跳过重建"降级路径需改为**硬失败**。
2. **申请授权**：联系 CHGIS（`chgis@fas.harvard.edu`）说明学术用途，申请书面许可（历史上有对学术项目放宽的先例，但需自行确认）。
3. **更换数据源**：改用许可条款允许再分发的高精度历史政区数据，代价是全链路重做（切片、地名映射、合规核对）。
4. **维持现状＋书面风险接受**：记录决策与理由，但需认识到该状态与 EULA 文本直接冲突。

> 附带项：仓库当前**无 LICENSE 文件**。自有数据（persons/relations/sources YAML）与代码的授权状态未声明，建议一并明确（例如代码 MIT／数据 CC BY-NC-SA 4.0，与已引入的 CBDB 条款保持一致）。
