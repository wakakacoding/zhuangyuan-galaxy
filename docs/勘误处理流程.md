# 勘误处理流程

> 状元星河数据勘误的接收、裁定与落地规范。M5 起生效。

## 通道

GitHub Issues → 「数据勘误」表单（`.github/ISSUE_TEMPLATE/errata.yml`）。
表单强制字段：涉及条目 / 现行记载 / 建议修正 / 证据等级 / 出处依据。**无出处依据的一律不采纳**，这是数据铁律。

## SLA

| 阶段 | 时限 |
|---|---|
| 首次响应（确认收到、归类 label） | ≤48 小时 |
| 裁定与处理完成 | ≤7 天 |
| 证据不足需补充 | 挂 `待补证`，30 天无补充则关闭并注明「可凭新证重开」 |

## Label 状态流

```
待核实 → 已采纳 / 异说并存 / 已驳回 / 待补证
```

## 裁定规则

1. **A 级证据 > B 级 > C 级**；高等级证据推翻低等级现行记载；
2. 同级证据相左（如 A 对 A）→ **异说并存**：条目挂 `disputed` 标记，两说并陈各挂出处，不强行二选一；
3. C 级单独不构成修改依据，仅作轶事/异闻收录（`anecdote` 标记）；
4. 拿不准的条目宁可挂存疑，不做「漂亮但没准」的修改。

## 落地规范

- 数据修订 commit 消息格式：`fix(data): <人物/条目> <简述> (#issue号)`；
  - 例：`fix(data): z0161 归佾 科年干支 申酉→辛酉 (#12)`
- 数据扩充 commit 格式：`feat(data): <批次/主题> <简述>`；
- 每处修订同步在 `data/CHANGELOG.md` 记一行（日期 / 条目 / 变更 / 依据 / issue 链接）；
- 采纳的 issue 在合并对应 commit 后关闭，并在 issue 中回贴 commit hash。

## 月度数据发布

每月末汇总当月数据变更（补录 / 修订 / 扩充三栏）入 `data/CHANGELOG.md`，打 `data-vYYYY.MM` tag。
